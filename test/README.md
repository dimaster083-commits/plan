# Проверки

Набор автоматических проверок приложения. Гоняет настоящий Chromium по
настоящему `index.html`: открывает экраны, нажимает кнопки, меряет пиксели
и сверяет числа. Сервер не нужен — приложение открывается как файл.

## Как запустить

```bash
npm install          # playwright-core и pngjs, один раз
npm test             # весь набор
```

Или подробнее:

```bash
node test/run.js                 # всё, кроме самопроверок
node test/run.js --self          # ещё и самопроверки
node test/run.js setka zavis     # только названные наборы
node test/run.js -j 1            # по одному (по умолчанию три разом)
```

Браузер ищется сам: сначала переменная `CHROME`, затем папка
`PLAYWRIGHT_BROWSERS_PATH` или `/opt/pw-browsers`, затем то, что скачал себе
playwright, затем системный chromium. Если не нашёлся:

```bash
CHROME=/путь/к/chrome node test/run.js
```

Снимки экрана, которые делают некоторые наборы, ложатся в `test/out/` — эта
папка не хранится в репозитории.

## Как это устроено

Каждый набор — отдельный файл в `suites/` и отдельный процесс: упавший
браузер не уносит с собой остальные. Набор возвращает ненулевой код, если
хоть одна проверка не прошла.

Новые наборы печатают каждую проверку строкой `✓` или `✗` — раннер их
считает. Старые печатают свой текст и сигналят только кодом выхода;
у них в колонке проверок стоит `—`. Это не значит, что они ничего не
проверяют.

**Правило, по которому они писались:** на каждую найденную ошибку пишется
проверка, которая **падает на старом коде**. Проверка, которая зелёная и до,
и после правки, ничего не стоит. Во многих наборах эта самопроверка стоит
прямо рядом — например, в `setka` последним пунктом идёт «со старой формулой
лёгкие упражнения застревали — сторож это видит».

Отдельно лежат `selftest*` — они нарочно возвращают уже исправленные ошибки
и убеждаются, что сторожа их ловят. По умолчанию не гоняются, потому что
намеренно воспроизводят старое поведение; запускаются флагом `--self`.

## Что чем покрыто

**Счёт и прогрессия**
`setka` — сетка весов и прибавки · `progr` — двойная прогрессия через
интерфейс · `spad` — снижение веса после двух провалов и честный значок на
облегчённой неделе · `obyem` — объём программы против её же нормы ·
`sverka` — вес в таблице плана совпадает с залом ·
`razgr` — неделя разгрузки не выглядит откатом · `tonn` — тоннаж считается
одинаково везде · `chisla` — каждое число пересчитано независимо ·
`logic` — опыт, ступени, серия · `rost`, `god` — год журнала целиком ·
`seria` — серия недель · `plan` — питание, ИМТ, переход недели

**Журнал и дни**
`den`, `dni` — экран дня и переходы · `istoriya` — история упражнения ·
`perenos`, `mvdone` — перенос и «выполнено» · `pravka` — правка дня ·
`cal`, `year` — календарь и год · `razbor`, `razbor2`, `temp2` — разбор

**Еда**
`eda`, `eda2` — рацион, шаблоны, выгрузка · `eda3` — своя база продуктов ·
`racion` — копирование рациона поверх дня · `pick2` — вид списка продуктов

**Вес, фото, добавки**
`ves`, `ves2` — вес как одна цифра на всё приложение · `napr` — кнопки
набор/похудение · `foto` — снимки и сравнение · `supp` — добавки

**Вёрстка и цвет**
`layout`, `shlay` — «дешевизна» глазами машины · `nalozh` — текст поверх
текста · `ovf`, `fit`, `dlinno` — влезает ли всё в телефон ·
`contrast`, `contrast2`, `sheets`, `calc` — контраст по настоящим пикселям ·
`palitra`, `slova` — чужие цвета и чужие слова в теме · `paltsy` — размер
кнопок под палец · `shapka` — шапка на всех ширинах · `rad` — диаграмма

**Целостность**
`mig` — переезды состояния на старом журнале · `press` — пресс как своя
мышечная группа · `krivoe` — кривое состояние в хранилище · `zavis` — негодная дата не вешает
приложение · `vosst` — восстановление из битой копии · `minus` — минус в
полях · `krai` — крайние состояния · `persist` — переживает перезагрузку ·
`monkey` — случайное тыканье не портит журнал · `hunt` — мёртвые кнопки ·
`smena` — смена темы не сбивает прогресс · `parity` — темы равны ·
`skroll` — прокрутка не прыгает · `tmr`, `tmr2` — таймер отдыха

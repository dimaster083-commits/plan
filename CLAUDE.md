# Дневник тренировок

Приложение целиком лежит в `index.html` — разметка, стили и код в одном
файле. Рядом только `sw.js` (офлайн-кэш), `manifest.webmanifest`, шрифты,
иконки и фотографии техники. Сборки нет: файл открывается как есть.

Выкладывается с ветки `main` на https://dimaster083-commits.github.io/plan/

## Логика тренировок

Правила ниже держатся на том, как устроены тренировки, а не на привычке.
Если правило мешает сделать приложение для зала лучше — его меняют, а
причину пишут сюда же (пересмотр владельцем, сентябрь 2026).

**Всё считается по журналу.** Тоннаж, подходы и рост берутся из
`dayEntries` / `dayTon` / `daySets` — из того, что человек записал, а не из
плана. Недельный баланс (`vol7m`) считает подходы тем же счётом, что `daySets`.

**Прогрессия двойная.** Вес растёт на шаг сетки, когда верх диапазона
закреплён (`maybeProgress`), и опускается на шаг после двух провалов низа
подряд (`maybeRegress`). Поднятый в подходе вес становится рабочим во всех
днях с этим упражнением (`bumpWorking`), только если низ диапазона добран в
каждом записанном подходе: одиночка на два повтора при плане 6–8 рабочим
весом не становится. Поменял цель в графе ПОВТ — она уходит во все дни
(`setReps`). Снятая отметка откатывает и вес, и цель. Клетки повторов
заранее заполнены целью от прошлого раза; пустая клетка значит «не записал»,
а не провал.

**Одна сетка весов.** `granOf` — килограмм до 20 кг, 2,5 кг выше. По ней
считают прибавку (`stepFor`), показ (`weightFor`), стартовый вес
(`startWeight`) и таблицу плана. Отдельного округления быть не должно: когда
прибавка и показ округляли по-разному, лёгкие упражнения застревали навсегда.

**Баланс — по мышцам, а не по группам.** «Руки» — это бицепс и трицепс,
«Ноги» — квадрицепс, бицепс бедра и икры (`MUSCLES`, `muscleOf`). Норма
мышцы — подходы, которые на неё ставит программа (`volTargetM`). Группы
(`GROUPS`) остаются для тоннажа за всё время.

**Серия недель — по настоящим тренировкам.** Неделя в серии, если закрыто
на одну тренировку меньше плана или больше (`weekNeed`, при 4 днях — 3).
«Пропуск» (`r.skip`) помечает день без опыта и тренировкой не считается.

**Питание и темп — по исследованиям, в одной модели.** Поддержание —
Миффлин — Сан Жеор × коэффициент активности, который выбирает человек
(`ACT`: 1,45 сидя, 1,6 на ногах, 1,75 физический труд; `maintOf`). Набор
+12 %, снижение −20 % (`nutriFor`). Коридор темпа в долях массы: набор
0,25–0,5 % в неделю, снижение 0,5–1 %, удержание ±0,25 % (`paceRange`). Темп —
наклон по всем взвешиваниям за 21 день (`paceOf`), поправка калорий от
разрыва, шаг 100–400 ккал (`kcalFix`). Разбор, график веса и «Расчёт» берут
цифры только отсюда.

**Первый запуск — без чужих цифр.** Поля первичной настройки пустые, вес
тела обязателен, без своих весов старт считается от веса тела.

**Вес человека — одна цифра.** Куда бы её ни вписали, путь один: `setBw`,
который пересчитывает нормы по еде и синхронизирует поля.

**Расписание — шаблон вт/чт/сб/вс** (`TPL`, решение владельца: своих дней
не нужно). `build()` и `S.days` обязаны совпадать.

**Отдых между подходами не рассчитывается** (решение владельца: сколько
отдыхать, человек чувствует сам). Таймер — только по его нажатию.

**Графа ПОВТ — цель программы, а не прошлые повторы.** Прошлый результат
виден строкой «в прошлый раз»; если подставлять его в графу, закрытый
подход через `setReps` переписывает цель во всех днях.

**Карточка упражнения думает за человека, но не решает за него.**
- Разминка (`warmupFor`) — мышце, а не упражнению: если мышца уже работала
  раньше в этой тренировке, разминки нет, и это написано. Штанга — с пустого
  грифа, лестница 50/70/85 % для силового диапазона (низ ≤ 6) и 50/75 % для
  объёмного; гантели и блоки — 50 % и 75 % на первом упражнении, иначе 50 %.
- Блины (`platesFor`) — на одну сторону грифа 20 кг, набор 25…1,25 кг; только
  для упражнений со штангой (`BARBELL`), подписи блинов не округляются.
- ≈1ПМ (`e1rmOf`, Эпли, до 12 повторов) — маленькой подсказкой, не целью.
- Подсказка веса (`weightAdvice`): если в прошлый раз было на 3+ повтора
  выше верха диапазона или на 2+ ниже низа, вес считается по ≈1ПМ на верх
  или на низ. Кнопка только вписывает цифру в поле, решает человек.
- Застой (`plateauOf`): три тренировки без роста ≈1ПМ — совет сменить
  диапазон или упражнение.

**Тоннаж за всё время — логарифмическая шкала 0,1…1000 т** (`volFrac`,
решение владельца), одна на все годы: ни одна полоса не упирается в край,
пока не набрано 1000 т. Больше тысячи тонн пишется в тысячах тонн.

**Дни недели наверху — не уже 44 px** даже на 320: ниже 375 px поля по
краям уходят, зазор 2 px.

## Оформление

**Тема одна — «Система».** Окна Системы из «Поднятия уровня в одиночку»
(синева, голубое свечение, фиолетовая аура), сведённые с инженерным
«Чертежом» с сайта методики: сетка-ватман, прорисовка штрихом, вспышка
рамки под пальцем, моноширинные подписи с «//», кольца-пульсы. Действующий
слой — последний блок стилей «КИБЕР-СИСТЕМА»; токены цвета — в «РЕДИЗАЙН
2026», блоки выше перекрыты. Анимации — только transform и opacity; у всего,
что прорисовывается штрихом, есть конечный вид для «Уменьшения движения».
Подписи — в словаре `DICT` (`T(key)`). `data-skin` всегда `sl`. Графика своя
(заставка — окно Системы, иконка — шестигранник), чужого арта нет.

**Под телефон.** Всё влезает в 320 px. Кнопка не меньше 44×44.

## Техника

**Номер переезда занимать нельзя.** `S.migN` — ключ в хранилище. Занял
чужой номер — чужой переезд молча не состоится; так один раз потерялись цель
по весу и рост. Новый переезд берёт следующий свободный номер и встаёт в
конец `migrate()`. Переезды двигают данные только у тех, кто пришёл со
старым состоянием.

**Каждая выкладка меняет ключ кэша** в `sw.js` (`sys-gym-NN`), иначе
телефон покажет прошлую сборку.

## Проверки

```bash
npm install && npm test
```

Подробности — в `test/README.md`. Главное правило: на каждую найденную
ошибку пишется проверка, которая **падает на старом коде**. Проверка,
зелёная и до, и после правки, ничего не стоит.

## Хранилище

Состояние — в `localStorage` под ключом `sys-gym-v3`, фотографии — в
IndexedDB `sysgym-ph`. `load()` прогоняет состояние через `scrubKeys()` и
`migrate()`: копия может быть старой, правленой руками или битой, и мусорный
ключ в журнале когда-то ронял «Прогресс» целиком. Восстановление из копии
идёт тем же путём.

# Реестр ошибок и ограничений «Системы»

Базовая версия: **1.4.8.8.1**, исходный коммит `4d8d72b`.
Аудит завершён в описанном покрытии. Текущий этап: согласованный первый цикл
исправлений BUG-0001/0002/0005 и связанной находки BUG-0019 опубликован
и проверен локально/на сайте, без изменения остальных продуктовых договорённостей.

## Как вести реестр

- Подтверждённые ошибки получают постоянные ID `BUG-0001`, `BUG-0002`, …
- Локальные номера находок агентов связываются с одним постоянным ID после
  проверки корневым агентом; похожие симптомы не считаются одной причиной автоматически.
- Ограничения и непроверенные предположения имеют отдельные ID `LIMIT-…`.
- Карточка: версия/среда, источник сообщения, приоритет, шаги, ожидаемое/фактическое,
  причина с местом исходника, затронутые экраны, воспроизводящая проверка,
  версия исправления, результаты отмены/перезагрузки/связей, публикация, ответ владельца.
- Статусы: сообщено → воспроизведено → исправлено → проверено → опубликовано
  → подтверждено владельцем. Нельзя перескакивать через неизвестные состояния.
- Повтор: тот же ID возвращается в «сообщено/воспроизведено», предыдущие
  доказательства остаются, записываются новая версия и условия повторения.
- Приоритеты: P0 массовая/невосстановимая потеря данных или невозможность открыть;
  P1 основной рабочий сценарий или ошибочное удаление с доступной отменой;
  P2 неверные итоги или отдельная функция; P3 удобство/оформление.

## Первый цикл исправлений (1.4.8.8.2)

- BUG-0001: код исправлен; сброс очищает только тренировку, сохраняет
  рацион/массу/заметки/добавки/исторический тип дня. Рекорды и цепочки
  рабочих весов/повторов проверяются вместе с отменой.
- BUG-0002: код исправлен; дата фиксируется перед подтверждением,
  снимок отмены — после ожидания непосредственно перед изменением.
- BUG-0005: код исправлен; дата передаётся с показанной кнопки каталога,
  проверки отдыха/дублей остаются перед записью.
- BUG-0019: код исправлен; однозначные цепочки откатываются по новым
  значениям отдельных операций, независимо от порядка индексов записей.
- Проверки и границы: `docs/audits/1.4.8.8.2/stage-1.md`.
- Полный локальный прогон: 145 наборов / 1413 проверок, exit 0, 508 с.
  BUG-0001/0002/0005/0019 проверены локально и на опубликованном сайте (22/22).
  Публикация подтверждена, runtime-коммит `4107128`, кэш 176.
  [Полный CI кода](https://github.com/dimaster083-commits/plan/actions/runs/38025652106)
  на момент записи ещё выполняется; фактический статус доступен по ссылке.
  Остальные 15 ошибок
  остаются открытыми. Само изменение кода не равно завершённому выпуску.

## Очерёдность следующих циклов

1. Защитить адресата действий: дата фиксируется для открытого подтверждения/
   карточки, старое окно не выполняет действие по новому `sel` (BUG-0002/0005).
2. Согласованный сброс только тренировки (BUG-0001) проверяется в первом цикле.
3. Валидация **до** преобразования и сохранения во всех формах: сохранять
   недопустимый черновик, проверять finite и границы; не лечить число0 вместо
   объяснения ошибки (BUG-0004/0007/0008/0010/0015).
4. Защитить геометрию повторного касания и черновики при любой смене вида,
   не только× (BUG-0003/0009/0014).
5. Исправить историю серии и честную обработку частичного восстановления,
   ошибок удаления/undo фото, проверять даты импортируемых фото;
   затем сообщение retry и доступность настроек
   (BUG-0013/0011/0016/0017/0018/0006/0012).

Для каждого исправления сначала воспроизведение RED, затем тот же сценарий
GREEN, undo/reload/связанные экраны, полный релизный прогон и CI. Следующий
номер **1.4.8.8.2** только для реально выпущенного исправления, не для отчёта.
Этот план не разрешает автоматически
менять модель старых нутриентов или значение0 веса строки.

## Известные ограничения до аудита

### LIMIT-001 — физические телефоны и Safari

- Тип: пробел покрытия, не подтверждённый дефект.
- Версия: 1.4.8.8.1.
- Статус: не проверено.
- Имеющиеся проверки: Chromium, синтетические отдельные контексты 320/390 px.
- Физические Android/iPhone и Safari этим не заменяются.
- Источник: `docs/audits/2026-10-09-linked-app.md`, раздел «Ограничения».

### LIMIT-002 — нулевой вес строки

- Тип: действующая договорённость, возможная неоднозначность интерфейса.
- Версия: 1.4.8.8.1.
- Пустая строка веса и 0 используют общий вес упражнения. Без отягощения
  общий вес должен быть 0. Изменение смысла 0 потребует отдельного решения
  о старых данных; само по себе это не вновь обнаруженная ошибка.
- Статус: ограничение; не исправлялось и не мигрировалось.
- Источник: `CLAUDE.md`, `docs/audits/2026-10-09-linked-app.md`.

### LIMIT-003 — неполный снимок исторического расписания

- Тип: известный исторический случай, требуется отдельное воспроизведение.
- Версия: 1.4.8.8.1.
- Исторический снимок хранит тип/название, не полный состав упражнений.
  Удаление всех упражнений шаблона и исторический порог серии не покрыты
  узкой правкой `planWeek`; общая историческая неизменность не доказана.
- Статус: нуждается в проверке; не объявлен исправленным.
- Источник: `docs/audits/2026-10-09-linked-app.md`, раздел «Ограничения».

Часть про порог серии теперь воспроизведена как BUG-0013. Удаление всего
состава шаблона и влияние на прошлые нормы/цикл отдельно не проверены;
LIMIT-003 целиком не закрыт.

### LIMIT-004 — динамические нутриенты исторических продуктов

- Продуктовый вопрос, не подтверждённый новый дефект.
- FOOD-01: правка100→200ккал/100г своего продукта меняет прошлый итог
  125→250ккал при прежних имени, граммах и дате. База общая, snapshot нутриентов нет.
- Перед изменением требуется выбор: исправление общей базы распространять
  на историю или хранить состав продукта на момент еды.
- Удаление использованного продукта уже предупреждает, что старые строки
  перестанут считаться; это не переименовано в ошибку без пересмотра контракта.
- Источник: `docs/audits/1.4.8.8.1/food.md`.

### LIMIT-005 — независимость/границы текущего аудита

- Агент Прогресса остановился на лимите до проверки; выполнен root fallback.
- Агенты Еды/Каталога остановились после сохранения отчётов/probes;
  корневой агент повторил их целиком. Это проверено, но не пять успешно
  завершившихся независимых агентов.
- Taskplane отказал в служебной identity; workflow не sealed, ограничения
  не обойдены, `.taskplane/` сохранён. Нативные Codex-отчёты учитываются отдельно.
- Нативное файловое share-системное окно не проверено; PNG проверен через
  download-fallback с контролируемой browser capability, см. `prog.md`.
- Не покрыты все сочетания кнопок, все876 карточек, реальная мобильная
  клавиатура/Back, большой журнал, новый полный CI/релиз. Аудит не гарантия
  отсутствия остальных багов. Подробнее `coverage.md` и отчёты вкладок.

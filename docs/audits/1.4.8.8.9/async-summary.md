# Поздний отказ копирования сводки — воспроизведено, 15.10.2026

База: опубликованная1.4.8.8.8, `5bc3db5175bab600334d424dd8e21a79b6f3e44c`.
На момент этого воспроизведения приложение не изменялось. Позднее владелец
подтвердил точечный clipboard-вариант. Этот исходный отчёт не является
доказательством готового фикса; реализация/проверки — в `copy-summary-fix.md`.

## Граница и причина

`copySummary()` снимает текст до `await navigator.clipboard.writeText(text)`.
При отказе без проверки identity/открытости исходного окна добавляет textarea
в нынешний `shB` и вызывает `select()`. После ожидания там может быть другая
форма, закрытое окно или заново открытый «Разбор». Повторный отказ каждый
раз добавляет новый textarea вместо обновления одного блока.

Системный буфер обмена заменён только в отдельном синтетическом Chrome
контексте контролируемым Promise, отклоняемым DOMException NotAllowedError.
Реальный буфер пользователя не читался и не изменялся. UI/обработчики,
состояние и отрисовка настоящие; API-double только задаёт поздний отказ.
По этим опытам нельзя оценивать частоту такого отказа на настоящем телефоне.

## Подтверждённые случаи

-390px: «Прогресс» → «Разбор» → «Выгрузить данные» (writeText pending) →
  закрыть → «Замеры» → вписать87,5 → отклонить writeText. До: заголовок
  ЗАМЕРЫ, textarea0, фокус waist, raw87,5. После: тот же заголовок и raw,
  textarea1 со старой сводкой, фокус больше не waist. Потеря сохранённого
  журнала не установлена; подтверждены чужой блок и перехват фокуса.
-320/390px: закрыть исходный «Разбор» до отказа → textarea1 в скрытом окне,
  уведомление «Выдели и скопируй вручную», хотя поле недоступно для пользователя.
-320/390px: закрыть и заново открыть «Разбор» до старого отказа → старый
  callback вставляет textarea в новое окно и переводит туда фокус.
-320/390px: два отдельных отказа при остающемся открытым исходном «Разборе»
  → textarea2. Оба нажатия выдерживают настоящий260мс duplicate-tap guard.

Первые два случая закрытия/повторного открытия на320 повторены в расширенном
probe. Первая расширенная попытка остановилась с locator timeout: новый
клик попал под duplicate-tap guard. Это ошибка темпа обвязки, не новый дефект.
После отдельного контекста на каждый case и280мс между настоящими нажатиями
все6 расширенных наблюдений получены, exit0. Это наблюдательный probe,
не зелёная регрессия исправленного поведения.

## Предложенный ограниченный контракт

Сохранить identity исходного окна до await. Поздний отказ не меняет закрытое,
новое или повторно открытое окно и не забирает там фокус. В текущем исходном
«Разборе» ручное копирование остаётся доступным через один обновляемый блок.
Успех системного копирования и сам текст сводки не меняются; журнал/палитра
не затрагиваются. После одобрения нужен RED→GREEN, затем обычная регрессия.

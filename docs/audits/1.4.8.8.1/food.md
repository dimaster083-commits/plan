## Подтверждённые дефекты

Корневая перепроверка после остановки агента на лимите: весь probe повторён,
`NATIVE_EXIT=0`, по56 ожиданий на320/390, по7OBSERVED, fatal=false/pageerror=0.
Подтверждены FOOD-02/03/04; FOOD-01 остаётся продуктовым LIMIT, не BUG.

### FOOD-02 — P2: неверные калории своего продукта сохраняются как ноль

- Шаги: «Еда» → «+ ПРОДУКТ» → поиск `AUDIT Food` → калории `abc` → «ОБНОВИТЬ ПРОДУКТ».
- Ожидалось: отказ с понятным сообщением, прежняя числовая запись сохраняется; допустимый явный `0` остаётся отдельным случаем.
- Факт в обоих размерах: `S.myFood[].k = 0`, сообщение об обновлении; прошлые 125 г перестают приносить калории. Обновление применяется и при некорректном поле, подтверждения ошибки нет.
- Причина: `index.html:11264` без проверки преобразует все поля через `num`; `index.html:3516` превращает `NaN` в 0; `index.html:11279` заменяет строку базы.
- Доказательство: `FOOD-02 invalid calories rejected rather than zero saved = false`, `customKString` показывает `0`, `historicalKString = 0`.

### FOOD-03 — P2: числовое переполнение ломает итоги и сохранение

- Ветка граммов: заменить граммы гречки на `Infinity` или `1e309`, уйти с поля. Факт: `tKc = Infinity / 2980 ккал`, `tPr = Infinity / 170 г`; все суммы становятся бесконечными. Строка граммов сохраняется без проверки.
- Ветка своего продукта: точный поиск `AUDIT Food`, калории `1e309`, «ОБНОВИТЬ ПРОДУКТ». Факт: в памяти `k = Infinity`, прошлый день получает бесконечные калории; JSON записывает число как `null`. После reload `k = null`, прошлый день показывает 0 ккал.
- Ожидалось: только конечное неотрицательное число; некорректный ввод не портит рацион/базу и не превращается в другое значение после reload.
- Причина: `index.html:3516` не проверяет `Number.isFinite`; `index.html:11088` сохраняет граммы строкой; `index.html:10954` умножает текущие значения; `index.html:11264` сохраняет нефинитные нутриенты. Ремонт формы еды в `index.html:4450` проверяет объекты, но не такие значения.
- Доказательство в обоих размерах: `Grams input "Infinity" = false`, `Grams input "1e309" = false`, `FOOD-03 nonfinite custom calories rejected = false`, после reload `customKString` показывает `null` и `historicalKString = 0`. JSON вывода представляет бесконечные числа как `null`; строки `*KString` отличают исходную бесконечность от сохранённого `null`.

### FOOD-04 — P2: × молча теряет набранный свой продукт

- Шаги: «+ ПРОДУКТ» → поиск нового `AUDIT New` → вписать калории 200, белок 12,5 → × до сохранения в базу.
- Ожидалось: предупреждение о потере заполненной формы либо сохранение черновика. Это следует из защиты набранных данных в `CLAUDE.md`.
- Факт: подбор закрывается без вопроса, повторное открытие сбрасывает поиск и заполненные поля. Проверка отказа при закрытии выбранных каталожных позиций проходит: проблема относится именно к форме своего продукта.
- Причина: `index.html:11214` проверяет только `picked.length`; форму `nfN/nfK/nfP/nfF/nfC` не проверяет. `index.html:11138` обнуляет поиск при новом открытии, `index.html:11153` создаёт новую форму.
- Доказательство: `FOOD-04 closing unsaved custom-food form requests confirmation = false`, `closed=true`, `ask=false`.

## LIMIT: история считает нутриенты по общей текущей базе

Проба с названием `FOOD-01 historical custom-food calories immutable after catalog edit` фиксирует **продуктовый вопрос, не подтверждённый дефект**. При правке `AUDIT Food` с 100 до 200 ккал/100 г прошлые 125 г меняют вычисленный итог с 125 до 250 ккал. Сама историческая запись — имя, граммы, дата — не меняется. `mealSum` (`index.html:10954`) каждый раз обращается к `findFood` (`index.html:10952`) и общему `S.myFood`, отдельного снимка нутриентов дня нет. Канон явно запрещает переписывать продукты и граммы при смене нормы, но не устанавливает хранение старой версии нутриентов при исправлении базы. Нужен продуктовый выбор перед возможным изменением этой модели.

Удаление уже использованного своего продукта явно предупреждает, что строка останется, но перестанет считаться (`index.html:11245`), поэтому само это поведение не записано дефектом.

## Подтверждённые нарушения

### WO-02 · P2 · Двойной тап по «Начать» попадает в «Отменить начало»

Воспроизведено на 320×568 и 390×844. Открыть список упражнения с пустой тренировкой и нажать «Начать тренировку» дважды в одной точке с интервалом 40 мс (`locator('#fin').dblclick({delay:40})`).

Ожидание независимо от реализации: два быстрых касания одного главного действия оставляют тренировку начатой один раз, без её завершения/отмены. Это следует из правил защиты пальцев `CLAUDE.md:358`.

Факт — трасса настоящих событий:

```json
[{"id":"fin","text":"Начать тренировку","trusted":true},
 {"id":"woCx","text":"Отменить начало","trusted":true}]
```

После второго касания `t0=false`, `wo=0`, сообщение «Начало тренировки отменено». Тоннаж и опыт не начисляются. Величина/расположение панели меняются после первого нажатия; второй тап уже относится к появившейся кнопке отмены. Защита `tapKey` сравнивает имена кнопок и поэтому пропускает другой ключ; `FIN_GAP` защищает завершение, а отмена начала его не проверяет. Источники: `index.html:4863` (`tapKey`), `index.html:4875` (сравнение ключа), `index.html:5461` (появление отмены), `index.html:6734` (начало/завершение), `index.html:6770` (отмена); `system.css:160` (положение панели).

### WO-03 · P2 · Недопустимый вес строки становится допустимым после открытия карточки

Воспроизведено на 320×568 и 390×844. Открыть жим, вписать `abc` в «Вес, подход 1», нажать «К списку», снова открыть жим, нажать «Завершить упражнение». Контрольный сценарий в том же probe: без закрытия карточки `abc` отклоняется сообщением «Проверь вес в строках подходов».

Ожидание: навигация/перезагрузка сохраняет ошибочный черновик или явно сообщает о его сбросе. Нажатие завершения не должно автоматически заменять недопустимый текст действительным рабочим весом и начислять результат. Явный `0`, выбранный пользователем согласно LIMIT-002, — иной сценарий.

Факт: ещё при вводе `l.ws=[0,'','']`, хотя на экране остаётся `abc`. После открытия поле содержит `0`. Завершение больше не блокируется: `done=1`, `vol=1440`, `rs=[8,8,8]`, опыт 72→84, рабочий вес 60→62.5. В историю добавляется жим 60×8×3, общая нагрузка груди становится 2880 кг с учётом предыдущей записи. Это не ошибка самого правила `0=общий`; исходный недопустимый текст превращается в `0` до валидации.

Причина прослежена: `num` преобразует нечисловой текст в 0 (`index.html:3516`); обработчик веса строки сохраняет `num(x.value)` (`index.html:6001`); `repBoxes` заново выводит полученное число (`index.html:6220`); `canCompleteEx` проверяет уже преобразованную строку (`index.html:6386`). Контрольный случай и нарушающий его переход находятся в одном воспроизводимом probe.

## WO-01 снят: действующее ограничение веса 0

Проверено: явно вписанный 0 в строку при общем 60 сохраняет договорённость `0=общий вес`; три строки по 8 дают 1440 кг и ту же прогрессию, что пустые веса строк. Reload даёт тот же результат. Это **не расчётный дефект**: `docs/audits/2026-10-09-linked-app.md:95` и `BUGS.md:39` (LIMIT-002) явно сохраняют такую совместимость. Поля/сообщение «Вес: число от нуля» не объясняют специальный смысл 0; это UX-неясность, а изменение числового контракта требует отдельного решения и миграции.

## Инвентарь и проверенное покрытие

Probe выводит полный фактический инвентарь элементов с надписями/aria/data, размерами, disabled и readonly. На 320 дни недели имеют 44×44, кнопки типов/галочек 44×48, завершение 270.97×45.59, RPE не меньше 49.39×44, переходы упражнений 44×44. На проверенном открытом экране горизонтального переполнения нет.

Список: выбор семи дат, название дня, «Неделя», настройки, подсказки, строки открытия, «Заменить», «+ Упражнение», пропуск, совет «Понятно», начало/завершение/отмена начала, сброс дня, пять вкладок, полоса отмены.

Карточка: «К списку», техника по названию/фото, замена, общий вес/подходы/цель повторов, веса/повторы строк, смена типа, галочки, копирование предыдущей строки, явное завершение/снятие, RPE6–10, суперсет, заметка, график (если доступен), удаление, точки перехода, подсказки, кнопка тренировки ниже карточки. Инвентарь — не утверждение о полном кликании каждой кнопки.

Проверены самостоятельные последовательности:

- `2.5` и `13` подходов, обратный диапазон `8-6`, отрицательный общий вес, 0 повторов строки и `abc` веса: закрытие блокируется в открытой карточке без тоннажа.
- Пустой вес строки использует общий; явный 0 — LIMIT-002. Числа переживают reload.
- Последняя галочка и явная кнопка дают 1440 кг / 3 рабочих подхода; двойной тап частичной галочки оставляет одну отметку, reload её сохраняет без добавления нагрузки.
- Верх диапазона поднимает рабочий вес 60→62.5; RPE10 после закрытия возвращает 60 без изменения 1440 кг; снятие RPE возвращает 62.5; снятие выполнения возвращает 60 и 0 кг.
- Только разминки дают 0 рабочих подходов, 0 тоннажа, без прогрессии и нового рекорда. Начисление обычного опыта закрытия здесь не объявлялось ошибкой.
- Суперсет переходит к следующей карточке; отмена снимает запись/прогрессию. Открытая карточка остаётся следующей — контракт восстановления её номера не заявлен.
- Закрытие тренировки после выполненного упражнения добавляет 60 опыта; отмена возвращает незакрытую тренировку, сохраняя упражнение/тоннаж.
- Будущий день: завершение disabled, галочка блокируется без начала/нагрузки. День отдыха показывает карточку отдыха. Прошлая дата задана фикстурой, просмотр read-only; через настоящую «Править» и снятие выполнения очищается нагрузка/закрытие.
- Черновик 55 кг переживает «К списку»/открытие. Удаление с подтверждением оставляет второе упражнение, отказ от удаления старой истории сохраняет прошлый жим; отмена восстанавливает программу и черновик55.
- Разовая замена настоящими кнопками на жим гантелей очищает старый черновик, сохраняет историю; отмена возвращает прежний жим и55.
- Синтетическое поле еды `S.rec[дата].ml` сохраняется при закрытии/снятии/reload/замене. Это проверка сохранности записи, не полноценное выполнение ввода пищи или расчёта её нутриентов.

Не проверены: физический палец/клавиатура Android/iOS/Safari, HTTP service worker, полночь, два окна, глобальная замена/сброс дня/пропуск с поздней правкой, каждое смешанное расположение Р/О/Д, копирование предыдущего подхода, UI еды/графиков/месячных итогов, работа на крупном реальном журнале. Техника и все подсказки только инвентаризированы. Независимые результаты функций `dayTon/daySets/exSessions/S.vol` читались для связи результатов с журналом; это не визуальная проверка всех downstream экранов.

## Воспроизведение

Из корня репозитория в PowerShell:

```powershell
$env:CHROME='C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:NODE_PATH='C:/Users/ALFA-PROM/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules'
node test/audits/1.4.8.8.1/wo.cjs
```

Вывод — JSON-строки инвентаря, трассы/снимки каждого действия и итог. В обычном режиме exit0 означает завершённый сбор наблюдений, **не здоровье приложения**. Для независимых контрактных проверок `$env:AUDIT_STRICT='1'` включает exit1 при нарушении. Авария обвязки даёт exit2. Браузер и каждый context закрываются в `finally`; сервер не запускался. Ошибки ранних итераций фикстуры (отложенный setup, отсутствующие миграционные флаги, скрытые чипы при открытой карточке) устранены и не занесены в дефекты продукта.

Завершённый фактический прогон: 72 проверки/наблюдения, 4 нарушения контрактов (WO-02 и WO-03 по одному на каждый размер), 68 успешных проверок; JS `pageerror=[]` в обоих контекстах. Итоговая строка:

```json
{"summary":"AUDIT OBSERVATIONS; not a release-health claim","checks":72,"contractFailures":4,
 "failures":[{"name":"320x568 start double tap","id":"WO-02"},
 {"name":"320x568 invalid draft stays blocked after reopening","id":"WO-03"},
 {"name":"390x844 start double tap","id":"WO-02"},
 {"name":"390x844 invalid draft stays blocked after reopening","id":"WO-03"}]}
```

Корневой агент повторил весь probe с `AUDIT_STRICT=1`: те же72 наблюдения,
те же4 нарушения, `NATIVE_EXIT=1` — ожидаемый RED по пользовательскому
контракту. Сборщик не упал; исправления не вносились. Обычный предыдущий
exit0 и строгий exit1 различают завершённую проверку и исправность продукта.

Команда завершилась exit0; вывод при наблюдении отфильтрован `Select-String -Pattern '"name"|"clickTrace"|invalidWeightAfterReopen|summary|runtimeError'`. Синтаксис отдельно проверен `node --check test/audits/1.4.8.8.1/wo.cjs` (exit0). Строгий режим не запускался. Строка probe «cancel empty start» в этом прогоне проверяет итог пустого состояния после двойного тапа; отдельное одиночное нажатие отмены не является дополнительной проверкой, поскольку двойной тап уже отменил начало.

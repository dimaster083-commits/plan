# Мобильный интерфейс и фото — независимый проход

13.10.2026. Проверена текущая 1.4.8.8.5, HEAD `caccb68`; номер папки —
следующий цикл аудита, не заявление о выпуске 1.4.8.8.6. Runtime не изменён.
Прочитаны полностью CLAUDE.md и BUGS.md. Taskplane не использовался.

## Результат

Новых самостоятельных ошибок в проверенном проходе не установлено.
Повторены открытые BUG-0012 и BUG-0020. Для BUG-0020 уточнено последствие:
несохранённый замер исчезает при реальном повторном открытии после того,
как ожидающая отмена закрыла его окно. Это уточнение существующего ID,
а не новая независимая причина. Защита нативной фотографии и позднего
сохранения журнала проверена отдельно.

Текущая композиция, палитра и плотность открытой рабочей карточки сохраняются.
Предлагаются только три ограниченных улучшения ниже.

## Среда и проверки

Настоящий Chromium через Playwright: изолированные контексты 320×568,
390×844, 1280×900, Asia/Vladivostok, фиксированное 13.10.2026 12:00.
Собственный HTTP localhost на случайном порту; настоящие localStorage и
IndexedDB, изображения созданы canvas внутри синтетического профиля.
Service worker выключен, чтобы проверять ровно исходники. Пользовательские
профили, фотографии и резервные копии не читались.

`node test/audits/1.4.8.8.6/mobile-photos.cjs`: 126 assertions, exit0.
Exit0 означает завершение диагностического прохода, а не отсутствие
открытых ошибок: known-наблюдения намеренно печатаются отдельно.

- Все пять вкладок, нижняя панель, открытая рабочая карточка, страница
  каталога в шторке, история фото и сравнение: ширина документа совпадает
  с viewport, нет необрезанных элементов за его границами.
- Кнопки/селекты в этих состояниях имеют область минимум44×44; редакторы
  даты и добавок отдельно перечислены ниже, это input, не button.
- Все три размера используют `data-skin=sl` и текущую палитру system.css.
  Визуально просмотрены сохранённые открытые карточки 320/390. Старого
  визуального слоя в этих карточках не выявлено; это не проверка каждого

  Подсказка поверх неё является верхним `currentModal`; Escape закрывает
  сначала подсказку, затем основную шторку. После закрытия прокрутка
  разблокируется. Фото-история и сравнение возвращают фокус своим кнопкам.
- При reduced-motion в проверенной открытой карточке нет работающих
  анимаций; текст, цифры, поля и завершение упражнения видимы. CSS содержит
  явный конечный reduced-motion вид; все анимированные состояния целиком
  не проверены.
- Фото записано как JPEG в настоящую IDB; история и сравнение открываются;
  удаление/отмена возвращают точную строку картинки; перезагрузка повторно
  читает ту же фотографию. На каждой ширине нет pageerror.

Сохранённые `test/audits/1.4.8.8.6/mobile-current-320.png` и

## KNOWN BUG-0020 — поздняя отмена закрывает новое окно

Точный trigger: загрузить синтетическое фото → удалить с подтверждением →
нажать Undo, задержав только доставку oncomplete настоящей RW-транзакции →
Прогресс → Внести замеры → вписать85,5 в Талию → доставить oncomplete.
Нативный commit уже произошёл; никаких замен phPut/phGet/undoNow нет.

До completion: `shT=ЗАМЕРЫ`, `sh.on=true`, raw85,5, undo busy.
После: `sh.on=false`, raw85,5 ещё в скрытом DOM, сообщение «Отменено».
После настоящего повторного открытия спустя300мс: raw пустой на320,
390 и1280. Вопрос о закрытии грязной формы не появляется. Фото полностью
и правильно восстановлено в IDB, необработанной ошибки нет.

Причина: `undoNow`, `index.html:4784`, читает wasOpen только после await;
`index.html:4812–4813` закрывает нынешнюю шторку через sheetClose без проверки
идентичности и sheetDirty. `openMeas`, `index.html:12240–12249`, заново
строит поля из записанного S.meas; несохранённые значения скрытого DOM
не являются сохранённым черновиком. Предыдущая граница stage-4 «потеря
введённого не воспроизведена» не подтверждается расширенной цепочкой
повторного открытия. Для приоритета можно пересмотреть P3→P2 именно
из-за доказанной потери несохранённого замера, окончательный ID/приоритет
согласует основной аудит.

RED `test/suites/undo-modal-oct13.js` проверяет сохранение новой шторки,
raw-input, фокуса и блокировки прокрутки; существующая до Undo шторка
сохраняет прежнее поведение закрытия. Также проверены настоящая IDB,
единственная запись при повторном Undo, точная фотография/reload,
неперезапись нового сохранённого журнала и замена одной открытой шторки
другой во время ожидания. Тестовые отказы здесь — ожидаемый RED текущего
runtime, не повреждение хранилища владельца.
Итоговый расширенный RED: 56 checks / 8 failures, exit1 на `caccb68`.
Отказы: закрытое новое окно/потеря фокуса/scroll lock и закрытая заменившая
его шторка на каждой из двух мобильных ширин. Остальные48 проверок проходят.

## Три конкретных улучшения текущего интерфейса

1. Дать одинаковую кнопку настроек44×44 на всех пяти вкладках; использовать
   существующие openSettings и текущий размер/цветgear. Проверять фокус,
   выбранную дату и отсутствие записи при простом просмотре.
2. Увеличить эффективную цель изменения даты старта на Прогрессе до44px:
   #startIn109,2×37,5. Он растянут на `.dpick`, и самSPAN.dpick не создаёт
   более крупную label-область. Источник `.dpick`, `index.html:1808–1815`,
   исходный date-style `index.html:208`. Размер даты/текста можно сохранить,
   добавив вертикальный padding контейнеру; не менять структуру Прогресса.
3. Убрать тесное прямое редактирование добавок: в строке Еды input названия
   имеет21px, «как принимать»17,25px высоты. РодительSPAN.t без label;
   область вокруг поля не переводит фокус в него. Источники
   `index.html:388–391`, `index.html:5589–5593`. Поднять effective-области
   до44px в режиме редактирования или открывать отдельную существующую
   по стилю шторку кнопкой44px, сохраняя компактный read-view строки.
   Второй вариант требует защиты сырого ввода при×/Escape/Undo.

Короткие input — конкретное неудобство текущей плотности, отдельного
нового BUG-ID им не присваивалось: правило CLAUDE о44×44 явно говорит о
кнопках. Не предлагаются новые цвета, перестановка вкладок или замена
утверждённой композиции.

## Границы

Физические Android/iOS, Safari, системная камера/HEIC/EXIF, мобильная
клавиатура/Back, большие архивы, quota и delivery/SW не проверены.
Задержка native completion управляемая: это доказательство гонки обработчика,
не утверждение о частоте такой задержки на настоящем телефоне. Полный
npm test выполняет корневой агент; этим проходом он не запускался.
Все собственные браузеры/контексты/HTTP-серверы закрываются в finally.

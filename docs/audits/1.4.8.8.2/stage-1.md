## Регрессия самого hunt

Независимый агент воспроизвёл: при пустой начатой тренировке, истёкшем FIN_GAP
и уже видимом пояснении повторный fin.click() оставляет тот же текст/DOM,
но увеличивает noteSeq. Обработчик работает; исходный снимок hunt не видел
повторного пояснения. Точная последовательность первого CI без телеметрии
не установлена, воспроизводящий этот ложный сигнал механизм подтверждён.

В test/suites/hunt.js добавлен синхронный сценарий с тем же снимком: сначала
RED (1 ошибка), затем GREEN (6/6). Снимок учитывает noteSeq только при
видимом уведомлении. fin не исключён из проверки, продуктовые защиты и
общие таймауты не изменены. Перед восстановлением fixture пропускается
task turn, чтобы отложенная автоматическая отмена не захватила тестовые данные.
Агент независимо выполнил конечный fixture: S/finAt/noteSeq восстановлены,
undoRec отсутствует сразу и после 40 мс. В мутации только в памяти отключён
click-обработчик fin: регрессия стала RED, обход обнаружил действительно
мёртвую «Начать тренировку», ошибок JS нет. Реальный сломанный обработчик
по-прежнему обнаруживается, постоянного whitelist для fin нет.

Конечный полный локальный прогон после правки hunt: `npm test`,
**145 наборов / 1414 проверок**, exit 0, 764 с; hunt 6/6,

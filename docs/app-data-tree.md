# Одно дерево данных приложения

Согласованный принцип 06.10.2026: действие меняет первичную запись, затем
связанные экраны получают её производные. Отдельная цифра «для красоты»
не должна подменять журнал. Схема отражает существующую архитектуру;
это не утверждение, что проверены все возможные сочетания действий.

```text
Локальные данные владельца
├── План: дни, упражнения, рабочие веса, старт, цикл, паузы, разовые замены
│   ├── Тренировка выбранной даты: dayOf / dayLook / weightFor
│   ├── Норма мышц: volTargetM → баланс, карта, недельные/месячные итоги
│   └── Тип дня → расчёт питания и календарь
├── Журнал по датам: S.rec
│   ├── Подходы: веса, повторы, тип, отметки, RPE, завершение тренировки
│   │   └── dayEntries — единый рабочий счёт
│   │       ├── daySets / dayTon → сводка дня и история
│   │       ├── vol7m / rangeData → карта, баланс, неделя, месяц, PNG
│   │       ├── рекорды / ≈1ПМ → графики и ранги силы
│   │       └── завершение → опыт, квесты и следующий рабочий вес
│   ├── Еда: продукты и граммы конкретного дня → итоги питания
│   └── Вес/замеры по датам → график и темп изменения
├── Профиль: масса, цель, пол, возраст, рост, активность
│   └── Расчёт норм питания, темпа и относительных рангов силы
├── Каталог и личные привязки
│   ├── EXDB / EXLIB → техника, фото, тип движения, мышцы
│   ├── S.libEx / S.myEx → одно имя связано с нужным движением и мышцей
│   └── S.fav + программа + история → живой список «Мои»
├── Фото: IndexedDB по датам → просмотр и сравнение
└── Настройки отображения: яркость, подсказки, звук
    └── Меняют представление, не подходы, рацион или исторические веса

Любое изменение
└── первичная запись → сохранение / обновление производных → связанные экраны
    ├── отмена → прежняя запись + пересчёт + обновление экранов
    └── восстановление → проверка формы + ремонт + пересчёт + обновление экранов
```

## Правила связей

- Разминка и дроп не добавляют рабочий тоннаж и прогрессию. Отказной подход
  остаётся рабочим. В отчётах не подставляется общий вес вместо весов строк.
  Отдельные галочки `ck` — сохраняемая текущая работа; `dayEntries` и
  общие итоги принимают запись после закрытия упражнения (`done`). Это
  граница состояния, а не разные счётчики подходов на разных экранах.
  Явная кнопка и последняя галочка закрывают одну запись через `toggleSet`.
  Строки Р/Д могут закрыть упражнение, но не создают рабочую нагрузку.
- Правка шаблона не переименовывает и не переписывает выполненную историю.
  Замена только на дату и замена в программе — разные действия.
- Цвет нагрузки зависит от записанных рабочих подходов и нормы плана.
  Красный означает выполненный план, не медицинскую оценку усталости.
  Вторичные мышцы на странице техники — анатомическое пояснение; они не
  получают выдуманные подходы в журнале.
- Яркость меняет только цвет. Статусы, числа, норма и длина полос остаются
  прежними; карта, баланс и итоги используют одну палитру.
- Короткий каталог — 40 основных движений, а не удаление базы 876. После избранного, добавления,
  отмены и импорта принадлежность «Моим» читается из текущего состояния.
  Одинаковый перевод не означает одинаковый id упражнения.
- Записанная еда принадлежит своей дате, а не общему шаблону дня недели.
  Изменение нормы не переписывает съеденные продукты и граммы.
- Сброс тренировки очищает только её журнал, завершение, время и пропуск.
  Еда, вес тела, заметки, добавки и исторический тип дня сохраняются.
  Тоннаж/опыт/рекорды пересчитываются по оставшемуся журналу; отмена
  возвращает весь снимок состояния, снятый непосредственно перед сбросом.
- Дата подтверждения сброса и дата кнопки каталога фиксируются при показе.
  Переход суток не перенаправляет уже открытое действие на новый день.
  Добавление из каталога сохраняет прежнюю модель общего слота программы
  (с учётом переноса даты); отдых и дубли проверяются ещё раз перед записью.
- Восстановление не смешивает старые вычисленные показатели с новым
  журналом. Фото восстанавливаются отдельно и не заменяют уже имеющееся
  личное фото той же даты.

# 1.4.8.8.5 — безопасные операции с фото

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Steps use checkbox syntax.

**Goal:** Исправить BUG-0011/0016/0017/0018 без изменения темы, тренировок и формата данных.

**Architecture:** Журнал остаётся в localStorage, фото — в IndexedDB. Импорт журнала и добавление архива не являются общей транзакцией: частичный результат сообщается явно. Проверка существующего снимка и вставка выполняются в одной readwrite-транзакции; невалидные даты не получают новую дату.

**Tech Stack:** Vanilla JS, IndexedDB, Playwright/Chrome, текущий Node test runner.

**Spec:** Контракт согласован владельцем в чате 13.10.2026: честный частичный импорт; собственные фото не заменяются; ошибочные даты исключаются; локальная обработка отказа удаления; никакой ложной успешной отмены. Источники: BUGS.md, docs/audits/1.4.8.8.1/photo.md и settings.md.

## Global Constraints

- Сохранить тему «Система», журнал, питание, замеры, вычисления и ключи sys-gym-v3/sysgym-ph.
- Не удалять существующие повреждённые ключи фото: исключать их из выбора.
- Оригинальный срок Undo — 7 секунд. Повтор отказавшей операции возможен в оставшийся срок; новое сохранение аннулирует старую отмену.
- Не выдавать синтетический storage fault за реальную квоту телефона.
- Публиковать только после проверок; bump SW cache 178 → 179.

## Review Focus

- Отказ чтения собственного фото не должен разрешить его замену.
- Abort транзакции без error должен отклонить Promise, а не повесить приложение.
- Изменение журнала во время await Undo не должно откатиться поздним результатом.
- Сбой чтения списка не должен выглядеть как пустой архив.
- Невозможная календарная дата не должна попасть в sel или ссылку истории.
